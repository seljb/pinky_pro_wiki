# pinky_navigation: maps, localization, planning and web control

## 1. Package overview

`pinky_navigation` assembles external Nav2 and SLAM Toolbox nodes, supplies Pinky-specific configuration and maps, and adds a browser interface. It does not implement a new path-planning algorithm in this repository: the YAML selects external planner and controller plugins. **[Code verified / 코드 확인]** [pinky_navigation/params/nav2_params.yaml:78–83](https://github.com/seljb/pinky_pro/blob/014a09f289e6988894fbffde2624fdb1e257815b/pinky_navigation/params/nav2_params.yaml#L78-L83); [pinky_navigation/params/nav2_params.yaml:266–284](https://github.com/seljb/pinky_pro/blob/014a09f289e6988894fbffde2624fdb1e257815b/pinky_navigation/params/nav2_params.yaml#L266-L284)

Think of navigation as three questions: “Where am I on the map?”, “Which route reaches the goal?”, and “Which velocity should I send now?” Localization, planning and control answer different questions. This is a learning interpretation of the configured AMCL, planner and controller components, not a measured runtime result. **[Inference / 추론]** [pinky_navigation/launch/localization_launch.xml:17–39](https://github.com/seljb/pinky_pro/blob/014a09f289e6988894fbffde2624fdb1e257815b/pinky_navigation/launch/localization_launch.xml#L17-L39); [pinky_navigation/launch/navigation_launch.xml:21–93](https://github.com/seljb/pinky_pro/blob/014a09f289e6988894fbffde2624fdb1e257815b/pinky_navigation/launch/navigation_launch.xml#L21-L93)

The package has its own `nav2_web_server.py` executable. The remaining launched navigation servers are external packages. CMake installs the Python script and adjacent HTML/logo under `lib/pinky_navigation`, and launch/params/map/RViz assets under `share/pinky_navigation`. **[Code verified]** [pinky_navigation/CMakeLists.txt:26–39](https://github.com/seljb/pinky_pro/blob/014a09f289e6988894fbffde2624fdb1e257815b/pinky_navigation/CMakeLists.txt#L26-L39)

## 8. Verification and open questions

**[Code verified]** The pages trace tracked source at the metadata SHA. **[Unverified / 미검증]** Build success, installed Nav2 behavior, lifecycle activation, action completion, real frame/topic names, QoS compatibility, map suitability and physical motion.

A top-level lifecycle list omits `smoother_server` although navigation launch creates it. `gz_web_nav2` does not pass simulated time to its web node, while `gz_web_slam` does. ### Check yourself

1. Does starting this package's `bringup_launch.xml` start the motors or simulator? **Answer:** No such include is configured; robot/simulator data must come from the separate bringup path.
2. Is `smoother_server` the component publishing final motor velocities? **Answer:** No. The launch distinguishes path smoothing from `velocity_smoother`, which remaps smoothed commands to `cmd_vel`.
3. Does a configured speed prove the robot travels at that speed? **Answer:** No. It is a source value subject to runtime overrides, downstream limits and actual dynamics.
